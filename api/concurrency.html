Главная/Справочник API/java.util.concurrent

java.util.concurrent

Потоки, пулы, футуры и конкурентные коллекции

База: Thread и Runnable

java
// Runnable — задача без результата (функциональный интерфейс → лямбда)
Runnable task = () -> System.out.println("Выполняюсь в " + Thread.currentThread().getName());

Thread t = new Thread(task, "my-worker");
t.setDaemon(true);     // демон не удерживает JVM живой
t.start();             // ВАЖНО: start(), а не run()!
t.join();              // дождаться завершения (бросает InterruptedException)

// Thread.sleep — приостановка; прерывание обрабатываем честно:
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt();   // восстанавливаем флаг прерывания
}

ExecutorService: пулы потоков

java
// Фиксированный пул (для CPU-задач: N = число ядер)
try (var pool = Executors.newFixedThreadPool(Runtime.getRuntime().availableProcessors())) {
    Future<Integer> future = pool.submit(() -> heavyComputation());  // Callable → результат
    Integer result = future.get(5, TimeUnit.SECONDS);                // блокирующее ожидание
}   // close() = shutdown + ожидание задач (AutoCloseable с JDK 19)

// Для I/O-задач в JDK 21 — поток на задачу:
try (var vtPool = Executors.newVirtualThreadPerTaskExecutor()) {
    // ... см. руководство «Виртуальные потоки»
}

// Планировщик:
try (var sched = Executors.newScheduledThreadPool(2)) {
    sched.scheduleAtFixedRate(heartbeat, 0, 30, TimeUnit.SECONDS);
}

CompletableFuture: асинхронные цепочки

java
CompletableFuture<String> fetchUser = CompletableFuture
    .supplyAsync(() -> queryDatabase())                     // асинхронный этап
    .thenApply(user -> user.toUpperCase())                  // map
    .thenCompose(name -> CompletableFuture.supplyAsync(     // flatMap
            () -> name + "@" + fetchMailServer()))
    .orTimeout(3, TimeUnit.SECONDS)                         // таймаут (JDK 9)
    .exceptionally(ex -> "fallback@example.com");           // обработка ошибки

String email = fetchUser.join();

// Два независимых запроса параллельно, затем объединение:
CompletableFuture<Price>  p = CompletableFuture.supplyAsync(() -> getPrice());
CompletableFuture<Stock>  s = CompletableFuture.supplyAsync(() -> getStock());
CompletableFuture<View> both = p.thenCombine(s, View::new);
📘 Примечание
С JDK 21 большинство «реактивных» цепочек заменяется прямолинейным кодом на виртуальных потоках: блокирующий queryDatabase() внутри Thread.startVirtualThread проще читать и отлаживать. CompletableFuture по-прежнему уместен для композиции и таймаутов.

Синхронизация

java
private int counter = 0;

// 1. synchronized — встроенная блокировка (монитор)
public synchronized void increment() { counter++; }

// 2. Явная блокировка (для виртуальных потоков предпочтительнее!):
private final ReentrantLock lock = new ReentrantLock();
public void safeIncrement() {
    lock.lock();
    try { counter++; } finally { lock.unlock(); }
}

// 3. volatile — видимость изменений между потоками (но НЕ атомарность!)
private volatile boolean running = true;

// 4. Атомики — неблокирующие операции (CAS):
private final AtomicInteger atomicCounter = new AtomicInteger();
atomicCounter.incrementAndGet();
atomicCounter.updateAndGet(v -> v * 2);
// AtomicLong, AtomicReference, LongAdder (для горячей статистики)

Конкурентные коллекции и утилиты

КлассНазначение
ConcurrentHashMapПотокобезопасный Map без глобальной блокировки; computeIfAbsent, merge атомарны
CopyOnWriteArrayListСписок для частого чтения/редкой записи (слушатели событий)
BlockingQueue / ArrayBlockingQueueОчередь producer-consumer: put()/take() блокируются
SemaphoreСчётчик разрешений (ограничить число одновременных доступов)
CountDownLatchЖдать N событий (одноразовый)
CyclicBarrierN потоков ждут друг друга (многоразовый)
PhaserГибкий барьер с фазами
ExchangerОбмен данными между двумя потоками
ForkJoinPoolПул для divide-and-conquer задач (RecursiveTask), основа parallelStream()
java
// Классический producer-consumer:
BlockingQueue<String> queue = new ArrayBlockingQueue<>(100);

// producer (виртуальный поток):
Thread.startVirtualThread(() -> {
    while (true) queue.put(produceItem());     // блокируется, если очередь полна
});
// consumers:
for (int i = 0; i < 4; i++) {
    Thread.startVirtualThread(() -> {
        while (true) process(queue.take());    // блокируется, если очередь пуста
    });
}

Правила безопасной многопоточности

  1. Не разделяйте изменяемое состояние — лучшая синхронизация. Иммутабельные объекты (record, String) потокобезопасны по определению.
  2. Один лок — одна ответственность; держите synchronized-секции короткими, без I/O внутри.
  3. Всегда обрабатывайте InterruptedException: либо пробрасывайте, либо восстанавливайте флаг Thread.currentThread().interrupt().
  4. Используйте конкурентные коллекции вместо ручной синхронизации обычных.
  5. В JDK 21 для I/O — виртуальные потоки, для CPU — пулы по числу ядер.
⚠️ Внимание
Дедлоки возникают при захвате двух и более блокировок в разном порядке. Правило: фиксируйте глобальный порядок захвата или используйте lock.tryLock(timeout).
