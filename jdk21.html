Что нового в JDK 21

Релиз от 19 сентября 2023 года · LTS · 15 JEP'ов

JDK 21 — второй LTS-релиз после перехода на полугодовой цикл (предыдущие LTS: 8, 11, 17). Это один из самых «плотных» релизов за годы: виртуальные потоки вышли из инкубатора, switch научился сопоставлению с образцом, а коллекции получили единый порядок обхода.

Финальные возможности

Виртуальные потоки (JEP 444)

Главное событие релиза. Виртуальный поток — поток JVM, который не привязан 1:1 к потоку ОС: при блокирующей операции он «отсоединяется» от носителя (carrier thread), освобождая его для других задач. Подробный разбор — в руководстве по виртуальным потокам.

java
// Один виртуальный поток на задачу — можно создать хоть миллион
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    IntStream.range(0, 100_000).forEach(i ->
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));  // блокировка не занимает поток ОС
            return i;
        })
    );
}

Паттерны записей (JEP 440)

record можно деконструировать прямо в instanceof и switch — как кортежи в других языках:

java
record Point(int x, int y) {}
record Line(Point start, Point end) {}

// Деконструкция с вложенными паттернами
if (obj instanceof Line(Point(var x1, var y1), Point(var x2, var y2))) {
    double len = Math.hypot(x2 - x1, y2 - y1);
}

Сопоставление с образцом для switch (JEP 441)

switch теперь полноценное выражение сопоставления: по типам, с защитными условиями when и веткой case null:

java
static String describe(Object obj) {
    return switch (obj) {
        case Integer i when i > 100 -> "большое целое: " + i;
        case Integer i            -> "целое: " + i;
        case String s             -> "строка длиной " + s.length();
        case Point(int x, int y)  -> "точка (%d, %d)".formatted(x, y);
        case null                 -> "это null";
        default                   -> "другой тип: " + obj.getClass().getSimpleName();
    };
}

Последовательные коллекции (JEP 431)

Новые интерфейсы SequencedCollection, SequencedSet и SequencedMap унифицируют работу с началом и концом любой упорядоченной коллекции:

java
SequencedCollection<String> seq = new LinkedHashSet<>();
seq.addFirst("первый");
seq.addLast("последний");
String first = seq.getFirst();     // было: iterator().next()
String last  = seq.getLast();      // было: боль и страдания
var reversed = seq.reversed();     // представление в обратном порядке

Поколенческий ZGC (JEP 439)

Сборщик мусора ZGC (паузы < 1 мс) стал поколенческим: -XX:+UseZGC -XX:+ZGenerational. Молодое поколение собирается отдельно и чаще — выше пропускная способность, меньше расход памяти.

KEM API (JEP 452)

Новый криптографический API javax.crypto.KEM для алгоритмов инкапсуляции ключей — подготовка к постквантовой криптографии.

Прочие изменения

  • JEP 449 — устаревание 32-битного порта Windows x86.
  • JEP 451 — предупреждение об использовании агентов (-javaagent) без явного разрешения.
  • JEP 446/447 — улучшение инкапсуляции и производительности при работе с sun.misc.Unsafe (постепенная миграция на VarHandle/MemorySegment).
  • Обновления безопасности и сотни исправлений — см. OpenJDK issue tracker.
💡 Совет
Если вы стартуете сегодня — ставьте именно JDK 21 (или новее LTS): бесплатная поддержка Temurin/Corretto для 21 LTS длится годы, а весь современный код (виртуальные потоки, паттерны) уже стабилен.
